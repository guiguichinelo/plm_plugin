# PLM beta 5

Preserve personal-list membership and native favorite intent across catalog disappearance and item-ID changes. Reconcile unique, visible provider matches after scans settle, retain explicit unlikes and deletion markers, preserve list order/dates and current playback state, and keep unidentified or ambiguous matches pending.

Targets Jellyfin 12.4.0 on Linux x64. Requires matching Plugin Pages and File Transformation 3.0.3.0 Release-12.4.0 builds. Existing beta 4 layout, translations and navigation are retained.

Adds identity, alias, favorite-intent and reconciliation-log tables to the existing PLM database. Back up Jellyfin, PLM data and plugin binaries before upgrading. Earlier list tables remain readable by beta 4; downgrading disables the new protection and does not preserve changes made while that older plugin is running.

Protection starts only after PLM has observed an accessible item and its identity. Wait for the baseline to complete before testing catalog loss. This is preventive protection, not recovery of previously unknown orphaned items. Native playback-history restoration is outside this change.

Validated with 26 core and 14 HTTP tests and isolated Jellyfin catalog rebuilds, including loss of native UserData, changed paths/IDs, restarts, rebuilding without a restart, delayed metadata, duplicate provider matches and stale native likes. Live rebuild tests used synthetic movies; series/episode identity rules have unit coverage. Sustained load, other server versions, architectures and PostgreSQL remain unvalidated.

See [catalog resilience](../CATALOG-RESILIENCE.md) for matching rules and boundaries. Previous release archives remain immutable.

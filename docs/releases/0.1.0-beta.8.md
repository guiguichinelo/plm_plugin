# PLM beta 8

Support explicit Jellyfin version groups in personal lists and Watch Later, preserving original selections while displaying one card per group. Add transactional group removal/restoration, group-aware memberships, idempotent additions and pagination after grouping. Also include the beta 7 fixes for unavailable-item removal, native refresh controls and unrelated requests blocked by the mirror mutation gate.

Targets Jellyfin 12.4.0 on Linux x64. Requires matching Plugin Pages and File Transformation builds. Assembly version: 0.1.0.8. No database migration is required. Back up configuration, plugin binaries and personal data before updating.

The existing API remains available; clients opt into grouped responses with `groupVersions=true`. Native favorites and playback fields are not rewritten to simulate list membership. Group resolution checks user visibility and explicit version relations; it does not merge titles using names or external provider IDs.

Validation: 23 API and 26 core tests, browser regression checks and 64 interface locales. Live movie/episode merge and split, group removal/restoration, and access revocation were exercised on a test server. List queries hydrate the displayed page instead of every ordered result. These checks are not certification of sustained load capacity or all server/client versions.

Known limitation: legacy groups stored as `LocalAlternateVersions` are not detached by Jellyfin's native alternate-source split action. It can return HTTP 204 while those relations remain. PLM continues to reflect the relationships actually stored by Jellyfin; this release does not repair or migrate legacy local-version groups. For long Merge Versions operations, use scheduled tasks rather than overlapping manual requests. Merge Versions itself is not modified or bundled.

See [version-group API and behavior](../beta8-version-groups.md) and [beta 7 fixes](../beta7-fixes.md). Earlier public archives remain immutable.

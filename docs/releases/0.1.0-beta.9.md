# PLM 0.1.0-beta.9

Prevent native favorite actions from stalling behind catalog-resilience work and keep a concurrent unlike from being overwritten by a stale replay.

- Remove the monitor spanning calls into Jellyfin library and UserData services. Native callbacks can re-enter without waiting for the full background cycle.
- Coordinate explicit favorite mutations and resilience replay by user and item using a bounded set of gates. Playback-only updates remain independent.
- Revalidate the pending favorite revision under that gate before replaying it. Preserve explicit unlikes and every playback field.
- Keep catalog identity, conservative rebinding, original selections, version-group projection and unavailable-item removal unchanged.

Validated on Jellyfin 12.4.0, Linux x64 with core/API tests, a regression that reproduces the former cross-thread callback timeout, browser fixtures and short isolated API-load stages at 5, 10, 20 and 40 clients. The final load run preserved all acknowledged favorite/progress values and returned no HTTP errors. The 40-client stage exceeded the latency target on the constrained test instance, so this is not a sustained-capacity or streaming certification. No schema migration is required. Back up plugin binaries, configuration and data before updating; restart Jellyfin and reload existing web clients after installation.

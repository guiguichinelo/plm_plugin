# PLM architecture

PLM stores selections of existing catalog IDs, never copies media and never writes to Jellyfin's database directly. Jellyfin authenticates requests; the owner comes exclusively from its `Jellyfin-UserId` claim. An administrator has no PLM endpoint to browse another user's collections. Administrators with database/filesystem access remain trusted operators.

`Plm.Core` owns an independent SQLite schema with parameterized owner checks, transactional optimistic revisions, WAL, foreign keys, soft deletion and consistent backups. `Jellyfin.Plugin.Plm` adapts host authentication, library visibility, native progress, playlists, the administrator page and Plugin Pages. The user page uses the existing Jellyfin session; no second password, token persistence or external assets are introduced. Native Favorites remain Jellyfin Favorites.

The web client separates host integration (`navigation.js`), page activation/owned backdrop (`surface.js`), list/favorites data providers (`providers.js`) and browsing controls (`library.js`). Favorites queries and toggles use the host API directly. From beta 5, a private intent ledger remembers explicit favorite changes for catalog resilience; it does not replace native Favorites. A cached Plugin Pages view is reactivated explicitly, rather than relying on its inline script running again. Route visibility and the current owner guard asynchronous UI updates. Theme integration uses native computed image filtering and the existing theme background, without product-specific CSS imports or bundle edits.

Selections use the current catalog GUID. Beta 5 additionally remembers owner-scoped media identity and prior GUID aliases so a unique, verified item can be rebound after catalog loss. A missing or inaccessible entry remains selected, but its title, genres and other metadata are redacted. There is no matching by title or path. Watched entries are retained. Pagination defaults to 40 and permits at most 200 returned entries. Unfiltered list pages use indexed SQL LIMIT/OFFSET before metadata resolution. Filtered/sorted pages send only the owner's selection IDs into a user-scoped native catalog query; only the requested result page receives metadata. Filtering still costs more than ordinary pagination and needs sustained-load validation.

The mirror worker is opt-in. It runs serially and starts another cycle after 60 seconds. Each collection produces one private playlist per playable media family supported by the host. Series/seasons/albums expand into accessible leaves, using bounded queries and season/episode ordering. IDs are deduplicated. Unsupported native playlist types remain available in the PLM web view. Photos/books do not acquire playback support in a client that lacks it.

Every native playlist is recorded in the PLM ownership ledger. A global MVC filter denies native mutations addressed to those IDs and denies targeted reads by other accounts. Ordinary playlists are unaffected. Playback/user progress use the host's normal APIs. The worker rechecks visibility and current playlist contents each cycle, including when the collection revision is unchanged; permission changes are eventually reflected in mirrors. Jellyfin's own authorization remains necessary for catalog enumeration and playback. PLM is not a security boundary against other server plugins or filesystem administrators.

Soft-deleted collections and selections become eligible after 30 days. Active missing media never expires automatically. Mirrored collections retain their ledger until the worker removes derived playlist records. Deletion uses the host API with `DeleteFileLocation=false` and external deletion disabled. This preserves source files, and can leave host playlist metadata files on disk; do not rescan orphan playlist folders as imports. Missing accounts are suspended, tracked by GUID and purged after 30 days; new accounts with the same name inherit nothing. These account/derived-mirror checks also run with mirror synchronization disabled. Cleanup of user-deleted collections and selections is administrator-triggered.

Back up with `GET /PLM/v1/admin/backup`, which uses SQLite's online backup API, or stop Jellyfin before copying the database. Never copy a live `.db` alone while WAL is active. User export/import is JSON schema 1 and contains only that user's active lists/IDs. Import is atomic, creates new list IDs and never overwrites existing lists. Exported Watch Later imports as an ordinary list to preserve the receiving account's existing default list. Imported missing IDs stay unavailable until visible again. Restore a full database only with Jellyfin stopped and the matching plugin/schema version.

Media images, progress and availability come from Jellyfin. Private list thumbnails are capped at 512 KiB and stored as owner-scoped JPEG blobs in PLM SQLite; browser uploads crop/reencode to 512 square pixels. The server validates JPEG headers and a maximum 2048-pixel dimension. Authenticated thumbnail endpoints use private/no-store responses; no public image URLs are created. Database backups include thumbnails, while portable JSON exports contain list selections only. Soft-deleted list artwork is retained for restore, then removed during list cleanup; missing-account purge includes it. Sidebar artwork is lazy-loaded with a bounded browser cache. Uninstalling the assembly preserves `data/plm/plm.db`; managed native mirrors stop synchronizing and the PLM mutation filter is removed, so disable/delete derived mirrors before uninstalling if native editing must remain prohibited.

Administrators may set `DisableNativePlaylists=true`. This blocks native playlist controller routes, prevents mirror synchronization and hides native playlist navigation in the web client. The native Favorites destination and legacy Favorites URLs lead to the personal library; user preferences provide list administration. These request-time additions use File Transformation; installed web files remain unchanged. The administrator-only `POST /PLM/v1/admin/playlists/clear` removes playlist records using the host API with source-file deletion disabled; it requires native playlists to be disabled first. Back up the host database and quarantine obsolete playlist metadata folders separately to prevent later re-import. This operation does not clear PLM collections.

## Catalog resilience

Beta 5 adds identity, alias, favorite-intent and reconciliation-log tables to the same PLM database. Baseline capture and explicit native changes preserve intent independently of catalog entries. Missing entries never expire because a scan lost them. Rebinding requires a unique, visible provider match after the scan settles; unavailable metadata, conflicting providers and duplicate copies remain pending. Unlike/deletion markers take precedence over stale state. Native favorite replay changes only IsFavorite and preserves current playback data. See [matching rules and limitations](CATALOG-RESILIENCE.md).
